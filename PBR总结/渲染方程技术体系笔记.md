# 渲染方程技术体系概念辨析

> 整理自 2026-08-10 17:50 以后的渲染相关讨论

## 1. 渲染核心概念关系

### 1.1 问题：以下概念之间的关系？

render equation, LTE, ray tracing, path tracing, GI, 直接光, 间接光, primary ray, shadow ray, secondary ray, photon mapping, IBL, monte carlo

### 1.2 回答

**Rendering Equation / LTE** 是描述光在场景中如何传播、反射、吸收的理论基础，一切渲染算法本质上都是在数值求解这个方程。

$$
L_o(\mathbf{x}, \omega_o) = L_e(\mathbf{x}, \omega_o) + \int_{\Omega} f_r(\mathbf{x}, \omega_i, \omega_o) \, L_i(\mathbf{x}, \omega_i) \, (\omega_i \cdot \mathbf{n}) \, d\omega_i
$$

| 符号 | 物理意义 |
|---|---|
| $L_o$ | 从点 $\mathbf{x}$ 沿方向 $\omega_o$ 出射的辐射亮度 |
| $L_e$ | 该点自身发出的光（自发光） |
| $f_r$ | BRDF/BSDF，描述表面如何散射入射光 |
| $L_i$ | 从方向 $\omega_i$ 入射到 $\mathbf{x}$ 的辐射亮度 |
| $(\omega_i \cdot \mathbf{n})$ | 余弦权重（Lambert 定律） |

**光线分类**：

| 类型 | 作用 | 与 LTE 的关系 |
|---|---|---|
| **Primary Ray** | 从相机穿过像素发出的第一条光线 | 确定积分起点 $\mathbf{x}$ 和观察方向 $\omega_o$ |
| **Shadow Ray** | 从交点向光源发射，判断遮挡 | 计算直接光项中的可见性 $V(\mathbf{x}, \mathbf{x}')$ |
| **Secondary Ray** | 命中表面后继续反射/折射的光线 | 用于采样 $L_i$ 积分项，估计间接光 |

**光路分解**：

| 概念 | 定义 | 对应光线 |
|---|---|---|
| **直接光** | 从光源直接到达 $\mathbf{x}$ 的光 | Primary Ray 命中后发射 Shadow Ray 到光源 |
| **间接光** | 经其他表面反射/折射后再到达 $\mathbf{x}$ 的光 | Secondary Ray 继续追踪 |
| **GI（全局光照）** | 直接光 + 间接光的统称 | 完整的光传输过程 |

**求解方法**：

- **Path Tracing**：直接在 LTE 的积分域上进行 Monte Carlo 采样，无偏、易实现
- **Photon Mapping**：两步法（光子追踪 + 密度估计），有偏但一致
- **Monte Carlo**：不是渲染方法，而是 Path Tracing、Photon Mapping、IBL 采样等都依赖的数学基础
- **IBL**：不是求解方法，而是提供 LTE 中 $L_i(\omega_i)$ 项的光源表示

**关系总图**：

```text
                LTE / Rendering Equation
                         │
        ┌────────────────┼────────────────┐
        │                │                │
    L_e(自发光)    直接光项          间接光项
        │                │                │
        │         Shadow Ray         Secondary Ray
        │                │                │
        │           GI ←──────────────→ GI
        │                │                │
        ▼                ▼                ▼
   直接显示          光源显式采样      Path Tracing
        │           / MIS            / Photon Mapping
        │                │                │
        └────────────────┴────────────────┘
                         │
                  Monte Carlo 数值积分
                         │
                  IBL 提供 L_i(ω_i)
```

**一句话总结**：LTE 是方程，Ray Tracing 是框架，Primary/Shadow/Secondary Ray 是工具，Direct/Indirect/GI 是光路分解，Path Tracing 和 Photon Mapping 是求解算法，Monte Carlo 是数学基础，IBL 是光照数据来源。

## 2. 渲染概念另一个解释

#### 一、Render Equation：一切的起点

1986 年 James Kajiya 在那篇著名论文里给出的这个方程，是整个现代计算机图形学的"麦克斯韦方程组"：

$$L_o(p,\omega_o) = L_e(p,\omega_o) + \int_{\Omega} L_i(p,\omega_i) \cdot f_r(p,\omega_i,\omega_o) \cdot (\omega_i \cdot n) \, d\omega_i$$

翻译成人话：**从点 $p$ 沿方向 $\omega_o$ 射出的光 = 该点自己发出的光 + 所有入射方向上来的光，经 BRDF 反射后、再乘上余弦衰减的积分**。

关键认知：
- 那个积分里的 **$L_i(p, \omega_i)$ 本身又是一个 Render Equation 的解**——因为入射光可能来自另一个表面的反射
- 这意味着方程是**递归的、无穷嵌套的**：光在场景中弹射无数次，每一次弹射都贡献一部分
- **直接光 + 所有阶间接光**，全被这一个方程包圆了 

#### 二、Light Transport Equation：换个名字的同一件事

**Light Transport Equation（光照传输方程）** 和 Render Equation 本质描述的是同一个物理过程——能量（光子）在场景中的传输。有时文献里会把"在体积介质中传输"的更一般形式叫 LTE，而把"仅在表面间传输"的形式叫 Render Equation。但在绝大多数实时渲染语境里，**这俩词可以视为同义**。

#### 三、直接光 vs 间接光：按"弹射次数"分家

把 Render Equation 的无穷积分展开成"弹射阶数"来看：

| 类型 | 含义 | 例子 |
|---|---|---|
| **直接光 (Direct Light)** | 光源 → 表面 → 眼睛，**0 次中间反弹** | 太阳照在墙上、灯泡正下方 |
| **间接光 (Indirect Light)** | 光在表面间至少反弹 1 次才进入眼睛 | 红色墙壁把光染红照到天花板（color bleed）、光从门缝漏进暗室 |
| **全局光照 (Global Illumination)** | **直接光 + 所有阶间接光的合集** | 你要解的那个完整 Render Equation |

> 💡 所以"全局光"不是一个具体算法，而是一个**目标**——把所有直接+间接的光照贡献都算出来。Lightmap、Photon Mapping、Radiosity、Irradiance Cache、VXGI、Lumen……**全都是"全局光照"这个目标的 different implementations**。

#### 四、光线追踪 (Ray Tracing)：一种"逆向"的求解框架

Render Equation 是从光源出发正向积分，但那样效率极低（大部分光根本射不到相机）。**Ray Tracing 的核心思想是把问题反过来**：从相机出发，往场景里投射线，追踪每条线碰到的表面，再递归地处理反射/折射。

##### Primary Ray（主射线 / 视线）
从**相机（或者说像素）出发**，射向场景的第一根线。它的作用是**找可见性**——"这个像素看到的是哪个表面的哪个点"。这根线命中后得到 shading point，后续所有光照计算都在这个点上进行。

##### Shadow Ray（阴影射线）
在 shading point 处，为了判断"这个点能不能直接看到光源"，向**每个光源**发射一根线。如果线在到达光源前被别的物体挡住 → 处于阴影中，没有直接光贡献；如果直达光源 → 接收直接光。

> 这两根线是 Ray Tracing 里最基础的两种射线。**Primary Ray 解决"看到什么"，Shadow Ray 解决"哪些光源能照亮它"**。

##### 递归的间接光
直接光用 Shadow Ray 搞定后，为了算间接光，在 shading point 处沿 BRDF 重要性采样方向再投一根线（次级光线 / secondary ray），这根线命中另一个表面后，**在那个表面上继续递归地算 direct + indirect**——如此往复，直到光线能量衰减到阈值以下（Russian Roulette 提前终止）。

这就是**最经典的 Whitted-style Ray Tracing**：primary ray → 命中 → shadow ray 判直接光 → 反射/折射 ray 继续追 → ……

#### 五、路径追踪 (Path Tracing)：蒙特卡洛版的 Ray Tracing

Whitted 风格的光线追踪有个问题：它只能处理镜面反射/折射的离散方向，处理**漫反射**时会傻眼——漫反射是向半球内所有方向均匀（或按 BRDF 分布）发射光，不可能跟踪所有方向。

**Path Tracing 的解法**：对每个像素，**随机采样一条从相机出发的路径**（path），沿着这条路径在每个顶点按 BRDF 重要性采样下一个方向，一路走到光源或逃逸出场景，得到这条路径的贡献；然后**用蒙特卡洛方法求平均**——每个像素追踪成百上千条这样的随机路径，平均起来就是无偏的 Render Equation 解。

```
Path Tracing 伪代码：
for each pixel:
    color = 0
    for i in 1..N_samples:
        path = [camera]
        throughput = 1.0
        while not terminated:
            hit = trace(path.last())
            if hit is light:
                color += throughput * Le
                break
            # 直接光照部分：从当前点向光源采样
            color += throughput * direct_light_contribution(hit)
            # 间接光照部分：按 BRDF 采样下一方向
            new_dir = sample_brdf(hit)
            throughput *= brdf_eval(hit, new_dir) * cos_theta / pdf
            path.append(trace(hit, new_dir))
    color /= N_samples
```

Path Tracing 的优势：**无偏、能处理任意 BRDF、理论上收敛到真实解**。代价：方差大、收敛慢，需要大量样本才能消除噪点——这就是为什么离线渲染一帧要渲几小时到几天。

#### 六、双向路径追踪 (Bidirectional Path Tracing, BDPT)

Path Tracing 从相机端出发，有个致命弱点：**对某些光照情况效率极低**。比如：
- 光源很小，从相机出发的路径很难"碰巧"命中它 → 漫反射间接光极难收敛
- Caustics（焦散）：光通过镜面/折射聚焦到漫反射表面（如水池底的花纹），从相机出发的路径几乎不可能复现这条光路

**BDPT 的思路**：**同时从相机端和光源端各发一条子路径**，然后在两条子路径的顶点之间"连接"起来形成完整路径。这样：
- 相机子路径捕捉"眼睛能看到什么"
- 光源子路径捕捉"光从哪里来"
- 两者的顶点组合能**高效覆盖各种光路**，特别是焦散和微小光源的间接照明

代价是实现复杂（需要处理路径连接的有效性、MIS 权重），但**对困难光照场景的方差降低是指数级的**。

#### 七、一张图串起所有概念

```
          Render Equation / Light Transport Equation
                         │
                         ▼
                    全局光照 (GI)
                  ┌──────┴──────┐
                  直接光        间接光
                  │            │
                  │            ▼
                  │       Path Tracing / BDPT
                  │            │
                  ▼            ▼
            Ray Tracing 框架
            ┌─────┬─────┬──────┐
            ▼     ▼     ▼      ▼
        Primary Shadow  Secondary  ...
          Ray   Ray    Ray
            │            
            └──── 求解 Render Equation 的数值方法
```

**核心 takeaway**：

- **Render Equation** 是理论，**Ray Tracing / Path Tracing** 是它的数值求解器
- **Primary Ray** 找可见表面，**Shadow Ray** 判直接光遮挡，两者是光线追踪最基本的两种射线
- **直接光 + 间接光 = 全局光照**，这是一个目标，不是算法
- **Path Tracing** 是蒙特卡洛化的光线追踪，无偏但慢；**BDPT** 是 Path Tracing 的加强版，双向出击，专治各种难收敛
- 实时渲染（如 UE5 Lumen）用的是这些理论的**近似版**——用 Signed Distance Field 或 Hardware RT 加速，牺牲一些物理精度换 60 FPS

---

**所以这套词汇在你写 shader、看渲染论文、调 UE5 的时候是这样呼应的**：
- 你写的 `radiance = direct + indirect` → 就是 Render Equation 的离散版本
- UE5 里 Lumen 的 `Final Gather` pass → 本质是**屏幕空间内的路径追踪近似**
- 电影渲染器（RenderMan、Cycles、Arnold）→ 跑的就是 BDPT 或 MegaPath Tracing
- `primary ray` 在你的光线追踪 shader 里就是 `rayOrigin = cameraPos; rayDir = computeRayDir(uv)`

## 3. 求解渲染方程的技术体系

### 3.1 问题：为了求解渲染方程，人们都做了哪些工作？

### 3.2 回答

#### 3.2.1 解析与近似方法（早期）

| 方法 | 核心思想 | 局限 |
|---|---|---|
| Phong / Blinn-Phong | 经验公式近似直接光反射 | 不基于物理，无法处理 GI |
| Lambert + 镜面分解 | 拆成漫/镜两项分别处理 | 忽略相互反射 |
| Whitted-style Ray Tracing (1980) | 递归追踪镜面反射/折射 | 无间接漫反射 |

#### 3.2.2 Monte Carlo 方法（无偏/一致）

| 方法 | 核心思想 | 关键人物/时间 |
|---|---|---|
| **Path Tracing** | 从相机出发随机走光路径 | Kajiya, 1986 |
| **BDPT** | 同时从相机和光源出发，连接子路径 | Veach & Guibas, 1995 |
| **MLT** | 用 MCMC 在路径空间按贡献采样 | Veach & Guibas, 1997 |
| **Photon Mapping** | 光子追踪 + 密度估计 | Jensen, 1996 |
| **PPM / SPPM** | 渐进式光子映射 | Hachisuka et al., 2008/2009 |
| **VCM** | 结合 BDPT 与 Photon Mapping | Georgiev et al., 2012 |

#### 3.2.3 有限元方法

| 方法 | 核心思想 |
|---|---|
| **Radiosity** | 将表面划分为元素，求解元素间能量交换 |
| **Hierarchical Radiosity** | 分层聚类 patch，降低计算量 |
| **Wavelet Radiosity** | 用小波基表示辐射度函数 |

#### 3.2.4 混合与双向方法

| 方法 | 核心思想 |
|---|---|
| BDPT + MIS | 双向路径 + Multiple Importance Sampling 加权 |
| Photon Mapping + Final Gather | 光子图估计间接光，Final Gather 降噪 |
| Instant Radiosity | 把光源变成虚拟点光源（VPL）近似 GI |
| Lightcuts | 用光源树聚类大量 VPL |

#### 3.2.5 加速结构与重要性采样

| 方向 | 代表工作 |
|---|---|
| 加速结构 | KD-tree, BVH, SBVH, Embree, OptiX |
| BRDF 重要性采样 | GGX、Beckmann、Lambert 等 |
| 光源采样 / MIS | Multiple Importance Sampling (Veach, 1997) |
| 环境贴图采样 | 按亮度分布采样 IBL 方向 |
| Russian Roulette | 按贡献终止低贡献路径 |
| Next Event Estimation | 每步都尝试直接连接光源 |

#### 3.2.6 参与介质与体积渲染

| 方法 | 核心思想 |
|---|---|
| Volume Rendering Equation | LTE 的体积形式 |
| Delta Tracking / Ratio Tracking | 无偏体积自由程采样 |
| Photon Beams | 光子映射的体积扩展 |

#### 3.2.7 实时近似方法

| 方法 | 核心思想 |
|---|---|
| Lightmap / Irradiance Volume | 预计算静态 GI，运行时查表 |
| AO / SSAO / SSDO | 屏幕空间近似遮蔽/方向光 |
| SSR | 屏幕空间反射 |
| RSM | 把光源渲染成 shadow map，间接光照近似 |
| LPV | 用体素传播间接光 |
| VXGI | 体素锥追踪近似 GI |
| SDFGI | SDF 加速间接光计算 |
| RTX/DXR | 硬件加速 PT，逐步逼近 LTE |

#### 3.2.8 机器学习方法（近年）

| 方法 | 核心思想 |
|---|---|
| Neural Radiance Caching (NRC) | 神经网络缓存辐射度 |
| NeRF | 用 MLP 拟合场景的 5D 辐射场 |
| Neural Light Transport | 神经网络学习直接/间接光分解 |
| Path Guiding with NN | 用 NN 学习重要方向分布 |
| Denoising with CNNs | 少量样本渲染 + 神经网络降噪 |

**关系总览**：

```text
Rendering Equation / LTE
         ├── 解析/近似 ── Phong, Lambert, Whitted Ray Tracing
         ├── Monte Carlo ── Path Tracing, BDPT, MLT, Photon Mapping, VCM
         ├── 有限元 ── Radiosity, Hierarchical Radiosity
         ├── 实时近似 ── Lightmap, AO, SSR, LPV, VXGI, RTX
         ├── 体积扩展 ── VRE, Delta Tracking, Photon Beams
         └── 机器学习 ── NRC, NeRF, Path Guiding, Denoising
```

## 4. Lightmap / Irradiance Volume 与 IBL 的区别

### 4.1 问题：Lightmap / Irradiance Volume 是啥？IBL 吗？

### 4.2 回答

**不是 IBL。** Lightmap / Irradiance Volume 是"预计算静态 GI"的实时近似方案，而 IBL 是"来自无限远环境的光源"。

#### Lightmap（光照贴图）

把场景中**静态物体**的表面展开成 UV，预先计算出每个像素收到的间接光照（Diffuse Irradiance），烘焙成一张纹理。

| 优点 | 缺点 |
|---|---|
| 运行时极快（只需一次纹理采样） | 只支持静态几何和静态光源 |
| 噪声低、质量高 | 需要 UV 展开，占用内存 |

#### Irradiance Volume（辐照度体积）

在三维空间中放置**体素网格**，每个体素预计算并存储该位置的 Irradiance（常用球谐函数 SH 表示），让**动态物体**也能接收静态 GI。

#### 三者对比

| | Lightmap | Irradiance Volume | IBL |
|---|---|---|---|
| 来源 | 场景中所有光源/表面的间接光 | 空间中预计算的辐照度 | 来自无限远的环境贴图 |
| 范围 | 贴在物体表面，逐像素 | 三维空间，逐体素 | 来自无穷远处，逐方向 |
| 动态性 | 静态预烘焙 | 静态预烘焙 | 可运行时切换 |
| 适用 | 静态场景的 GI | 动态物体接收静态 GI | 环境光、室外、反射 |

**协同使用**：

```text
场景光照 =
    直接光（点光源/方向光/聚光灯）
  + IBL（来自无限远环境的天空/HDRI）
  + Lightmap（静态物体表面的预烘焙 GI）
  + Irradiance Volume（动态物体的静态 GI 近似）
```

## 5. IBL 球谐光与渲染方程技术流派

### 5.1 问题：IBL 球谐光又是啥？渲染方程更细的技术流派及研究问题？

### 5.2 回答

#### IBL 与球谐（SH）的关系

漫反射 IBL 项是半球积分：

$$
L_o(\mathbf{x}, \omega_o) = \frac{\rho}{\pi} \int_{\Omega} L_i(\omega_i) \, (\omega_i \cdot \mathbf{n}) \, d\omega_i
$$

实时渲染中每像素做一次环境贴图卷积太慢，于是把 $L_i(\omega_i)$ 投影到球谐函数基上：

$$
L_i(\omega) \approx \sum_{l=0}^{n} \sum_{m=-l}^{l} c_{l}^{m} \, Y_{l}^{m}(\omega)
$$

| 特性 | 说明 |
|---|---|
| 低频近似 | SH 通常只用 2~4 阶（4~16 个系数） |

## 6. IBL 是直接光、间接光还是环境光？

### 6.1 问题：IBL 是间接光还是直接光还是环境光？

### 6.2 回答

IBL 本质上是**一种光源表示**，它提供的是**环境光**；但它对某个着色点的贡献，既可以是**直接光**，也可以是**间接光**，取决于光路。

在 LTE 中，IBL 提供 $L_i(\omega_i)$ 项：

$$
L_o(\mathbf{x}, \omega_o) = \int_{\Omega} f_r(\mathbf{x}, \omega_i, \omega_o) \, L_i^{\text{IBL}}(\omega_i) \, \cos\theta_i \, d\omega_i
$$

| 光路 | 类型 | 说明 |
|---|---|---|
| 相机 → 表面 → 直接看到 IBL | **直接光** | 一次散射/反射就到达 IBL |
| 相机 → 表面 A → 表面 B → IBL | **间接光（对 A）** | 经多次反射/折射后才到达 IBL |

与相关术语的关系：

| 术语 | 含义 | 与 IBL 的关系 |
|---|---|---|
| 环境光（Ambient Light） | 传统图形学中一个经验常数 | IBL 是环境光的**物理正确版** |
| 直接光 | 从光源不经反射到达的光 | IBL 可以是直接光的一种来源 |
| 间接光 | 经反射/折射后的光 | IBL 也可以成为间接光的来源 |
| GI | 直接光 + 间接光 | IBL 是 GI 的输入光源之一 |

**一句话总结**：IBL 是环境光的一种物理表示；它对某个像素的贡献可能是直接光（一次到达 IBL），也可能是间接光（经其他表面反射后到达 IBL）。IBL 本身是光源，不是光路类型。

## 7. rasterization, ray casting, ray tracing, path tracing

### 7.1 时间线、关键人物与论文

| 技术 | 年份 | 关键人物 | 论文/著作 | 解决的问题 |
|---|---|---|---|---|
| **Rasterization** | 1960s | Ivan Sutherland | *Sketchpad* (1963), 早期图形硬件 | 将 3D 几何投影到 2D 屏幕，实现实时显示 |
| **Ray Casting** | 1968 | Arthur Appel | *"Some Techniques for Shading Machine Renderings of Solids"* | 从视点发射光线求交，判断可见性与简单阴影 |
| **Ray Tracing** | 1979 | Turner Whitted | *"An Improved Illumination Model for Shaded Display"* | 递归追踪镜面反射和折射光线，实现真实镜面效果 |
| **Distributed Ray Tracing** | 1984 | Robert Cook | *"Distributed Ray Tracing"* | 对运动模糊、景深、软阴影等分布采样 |
| **Radiosity** | 1984 | Goral et al. | *"Modeling the Interaction of Light Between Diffuse Surfaces"* | 漫反射表面间的间接光（有限元方法） |
| **Path Tracing** | 1986 | James Kajiya | *"The Rendering Equation"* | 完整求解 LTE，实现全局光照（漫反射+镜面+间接光） |

### 7.2 各技术解决的问题与关系

#### 7.2.1 Rasterization（光栅化）

```
3D 三角形 → 投影到 2D → 逐像素填充 → 着色
```

- **解决的问题**：如何快速将 3D 场景显示到 2D 屏幕
- **局限**：只处理从相机到表面的可见性，不追踪光的传播路径，无法处理反射、折射、阴影、间接光
- **补充手段**：Shadow Map、Screen Space Reflection、Lightmap 等都是对光栅化缺失光追能力的补丁

#### 7.2.2 Ray Casting（光线投射）

```
对每个像素发射一条光线 → 找最近交点 → 用局部光照模型着色
```

- **解决的问题**：精确的可见性判断和硬阴影
- **局限**：只有一条光线，无反射/折射/间接光
- **与 Rasterization 的关系**：Rasterization 解决"哪些像素对应哪些三角形"，Ray Casting 解决"从视线方向看到什么"，殊途同归但 Ray Casting 更物理

#### 7.2.3 Ray Tracing（Whitted-style 光线追踪）

```
Primary Ray → 命中表面
  → 镜面反射方向发射 Secondary Ray → 递归
  → 折射方向发射 Secondary Ray → 递归
  → 向光源发射 Shadow Ray → 直接光
```

- **解决的问题**：镜面反射、折射、硬阴影
- **局限**：只处理完美镜面（delta BRDF），漫反射表面不发射次级光线，**无间接漫反射**
- **与 Ray Casting 的关系**：Ray Casting 是"一条光线到表面就停"，Ray Tracing 是"递归追踪反射/折射"

#### 7.2.4 Path Tracing（路径追踪）

```
对每个像素重复 N 次:
  发射 Primary Ray → 命中表面
  → 按 BRDF 随机采样一个方向 → 发射 Secondary Ray
  → 命中下一个表面 → 继续采样 → ... → 终止
  → 累积路径贡献
平均 N 次结果 → 像素颜色
```

- **解决的问题**：**完整求解 LTE**，包括漫反射间接光、焦散、所有光路类型
- **与 Ray Tracing 的关系**：Path Tracing 是 Ray Tracing 的推广——把"只在镜面方向发一条"变成"按 BRDF 分布随机采样一个方向，重复很多次取平均"

#### 7.2.5 关系图

```text
Rasterization ─── 快速但无光传播
     │
     │  互补
     ▼
Ray Casting ───── 一条光线，局部光照
     │
     │  递归扩展
     ▼
Ray Tracing ───── 镜面反射/折射递归
     │
     │  随机采样扩展
     ▼
Path Tracing ──── 完整 LTE 求解（GI）
```

### 7.3 Path Tracing 的工作流程

**是的，你的理解基本正确**，但有几个细节需要澄清。

#### 7.3.1 完整流程

```python
for pixel in image:
    color = 0
    for sample in range(N):          # N 次采样
        ray = camera.generate_ray(pixel, sample)  # Primary Ray
        path_throughput = 1.0
        path_color = 0

        for bounce in range(max_depth):  # 递归弹射
            hit = scene.intersect(ray)
            if not hit:
                path_color += path_throughput * IBL(ray.direction)
                break

            # 直接光（Next Event Estimation）
            for light in scene.lights:
                shadow_ray, light_pdf = light.sample(hit)
                if not scene.occluded(shadow_ray):
                    path_color += path_throughput * BRDF * light.Li * cos_theta / light_pdf

            # 间接光：按 BRDF 随机采样一个方向
            new_dir, brdf_pdf = hit.BRDF.sample()
            path_throughput *= BRDF.eval(new_dir) * cos_theta / brdf_pdf
            ray = Ray(hit.point, new_dir)

            # Russian Roulette 随机终止
            if random() > survival_prob:
                break

        color += path_color

    pixel.color = color / N   # Monte Carlo 估计值
```

逐行解释 Path Tracing 中单次采样的递归弹射循环：

```python
for bounce in range(max_depth):  # 递归弹射
```

每次弹射对应 LTE 中一层积分的展开。LTE 是递归的：$L_i$ 本身又是另一个点的 $L_o$，每次弹射就是在展开一层递归。

---

**第一步：求交**

```python
    hit = scene.intersect(ray)
```

当前光线（Primary Ray 或上一轮的 Secondary Ray）与场景求交，找到最近的命中点。这是 LTE 中确定积分点 $\mathbf{x}$ 的过程。

---

**第二步：未命中 → 环境光**

```python
    if not hit:
        path_color += path_throughput * IBL(ray.direction)
        break
```

光线飞出场景，没有命中任何物体。此时光线方向的入射光来自 IBL（环境贴图）。

物理含义：这条路径的终点是环境光，贡献 = 路径上所有弹射的累积吞吐量 `path_throughput` × 环境光亮度 $L_{\text{IBL}}(\omega)$。

---

**第三步：直接光（NEE）**

```python
    for light in scene.lights:
        shadow_ray, light_pdf = light.sample(hit)
        if not scene.occluded(shadow_ray):
            path_color += path_throughput * BRDF * light.Li * cos_theta / light_pdf
```

这是 **Next Event Estimation (NEE)**——不等待路径碰巧命中光源，而是**主动向光源采样**。

| 变量 | 物理含义 |
|---|---|
| `light.sample(hit)` | 在光源表面上随机采样一个点，返回方向和概率 |
| `shadow_ray` | 从命中点到光源采样点的阴影光线 |
| `scene.occluded()` | 判断是否被遮挡（Shadow Ray 测试） |
| `light.Li` | 光源在该方向的辐射亮度 $L_e$ |
| `cos_theta` | $(\omega_i \cdot \mathbf{n})$，Lambert 余弦 |
| `light_pdf` | 采样概率密度 $p(\omega_i)$ |
| `path_throughput * BRDF * light.Li * cos_theta / light_pdf` | Monte Carlo 估计值 $\frac{f_r \cdot L_e \cdot \cos\theta}{p}$ |

**为什么需要 NEE？** 如果只靠 BRDF 采样，路径很难碰巧命中小面积光源（如灯泡），导致大量路径贡献为 0、噪声极高。NEE 主动连接光源，大幅降低噪声。

---

**第四步：间接光——BRDF 采样**

```python
    new_dir, brdf_pdf = hit.BRDF.sample()
    path_throughput *= BRDF.eval(new_dir) * cos_theta / brdf_pdf
    ray = Ray(hit.point, new_dir)
```

这是 LTE 积分的核心：**按 BRDF 分布随机采样一个方向，继续追踪**。

| 行 | 含义 |
|---|---|
| `BRDF.sample()` | 按 BRDF 概率分布采样一个出射方向 $\omega_o$，同时返回该方向的 pdf |
| `BRDF.eval(new_dir)` | 计算 $f_r(\omega_i, \omega_o)$ 的值 |
| `cos_theta` | $(\omega_o \cdot \mathbf{n})$ |
| `path_throughput *= ...` | 累积吞吐量：$\text{throughput} \leftarrow \text{throughput} \times \frac{f_r \cdot \cos\theta}{p}$ |
| `ray = Ray(hit.point, new_dir)` | 生成新的 Secondary Ray，下一轮 bounce 继续求交 |

**`path_throughput` 的物理含义**：从相机到当前弹射点，这条路径上所有反射/散射的累积衰减。它回答的是"光源发出的光，经过这条路径后还剩多少能到达相机"。

展开来看：

$$
\text{throughput} = \prod_{k=0}^{b} \frac{f_r(\mathbf{x}_k, \omega_{k-1}, \omega_k) \cdot (\omega_k \cdot \mathbf{n}_k)}{p(\omega_k)}
$$

每次弹射乘一个 $\frac{f_r \cdot \cos\theta}{p}$，就是 LTE 逐层展开的 Monte Carlo 权重。

---

**第五步：Russian Roulette 终止**

```python
    if random() > survival_prob:
        break
```

**为什么需要 RR？** 理论上路径可以无限弹射（LTE 是无穷递归），但贡献随弹射次数指数衰减。RR 按当前 `path_throughput` 的量级决定是否继续：贡献小的路径大概率被终止，贡献大的路径大概率存活。终止时不需要额外加权（因为存活概率已经编码在 `survival_prob` 中），保证 **无偏**。

---

### 7.4 整体流程图

```text
Primary Ray ──命中 x₀──┬── NEE: 向光源采样 → 直接光贡献
                        │
                        ├── BRDF 采样 → Secondary Ray ──命中 x₁──┬── NEE → 直接光
                        │                                         │
                        │                                         ├── BRDF 采样 → Ray ──命中 x₂── ...
                        │                                         │
                        │                                         └── RR 终止
                        │
                        └── RR 终止

path_color = Σ(每次弹射的 NEE 直接光) + 末尾的 IBL 环境光
最终像素颜色 = path_color / N_samples
```

## 8. lightmap的光源 物体需要都是静态的吗？存的是irradiance吗？是间接光还是直接光还是全局光？
这三个问题问得很到位，正好触及 Lightmap 的本质。逐个说清楚：

### 1. 光源和物体都需要是静态的吗？

**物体（接收光照的表面）：必须是静态的。** 这是 Lightmap 的根本约束——因为 Lightmap 是把光照结果"烤"进与几何体 UV 绑定的纹理里，如果物体会移动，UV 对应的世界空间位置就变了，烤出来的光照就错位了。所以：
- **静态物体** → 使用 Lightmap
- **动态物体**（角色、载具、可交互道具）→ 走 Light Probe / Light Probe Volume 这条路

**光源：不一定全部静态，但纳入烘焙的光源必须标记为 Baked 或 Mixed。**

现代引擎（Unity/Unreal）把光源分成三种模式 ：

| 光源模式 | 对静态物体的贡献 | 对动态物体的贡献 |
|---------|----------------|----------------|
| **Realtime（实时）** | 不进入 Lightmap，运行时实时计算 | 实时计算 |
| **Baked（完全烘焙）** | 直接光 + 间接光全部烤进 Lightmap | 不参与（动态物体只能通过 Light Probe 获得该光源的间接光） |
| **Mixed（混合）** | 间接光烤进 Lightmap；直接光运行时实时计算 | 实时直接光 + 通过 Light Probe 获得间接光 |

所以准确说法是：**只有被标记为 Baked 或 Mixed 的光源才会对 Lightmap 产生贡献**。纯 Realtime 光源完全不参与烘焙。

> 💡 这也是为什么 Mixed 模式流行——静态物体既能享受烘焙的高质量间接光，又能让直接光跟着光源实时变化（比如昼夜循环、开关灯）。

### 2. Lightmap 存的是 Irradiance 吗？

**传统意义上：是的，存的是辐照度（Irradiance）。** 

Irradiance 的定义是：到达表面某点、上半球的入射光在表面法线方向上的积分：

$$E_p = \int_{\Omega^+} L_i(\omega_i) \cos\theta_i \, d\omega_i$$

每个 Lightmap 纹素存储的就是这个值（RGB 三通道）。运行时渲染：

$$\text{FinalColor} = \frac{\text{Albedo}}{\pi} \times \text{LightmapSample}$$

把 Irradiance 与表面反照率相乘，得到最终出射光。

**但现代引擎做了扩展**，不止存一个标量辐照度：

- **Directional Lightmap（Unity）**：每个纹素存两份数据
  - 辐照度（L1 球谐的 DC 项）
  - 主导光照方向（L1 球谐的线性项）
  
  这样法线贴图还能和"主光照方向"做点积，保留表面细节的明暗变化 

- **SH Lightmap**：每个纹素存 L2 球谐（27 个 float），可以重建任意方向的漫反射光照，精度最高但占用大

- **RNM（Radiosity Normal Mapping）**：存 3 个方向（tangent/bitangent/normal）的辐照度，配合法线贴图使用，是 Valve 在 Source 引擎里推广的方案

> 💡 不管哪种扩展，**底层核心仍然是 Irradiance**——只是从"标量"升级成了"带方向信息的辐照度表示"。

### 3. 存的是直接光、间接光还是全局光？

**Full Bake 模式下：Lightmap 存的是全局光（Direct + Indirect 的总和）。** 

也就是说，每个纹素的值是：

$$E_p = \underbrace{\int_{\Omega^+} f_r \cdot L_i^{direct} \cdot \cos\theta \, d\omega_i}_{\text{直接光（含阴影）}} + \underbrace{L_i^{indirect}}_{\text{间接光（多次反弹）}}$$

- 直接光部分：通过对光源采样 + 阴影光线判断遮挡来计算，包含锐利阴影
- 间接光部分：通过 Path Tracing / Photon Mapping / Radiosity 计算多次反弹

两者加在一起烤进同一个纹素。

**但现代引擎经常把它们分开处理**：

Unity 的 Lightmapping 系统中：
- **Baked 光源** → 直接光 + 间接光都进入 Lightmap
- **Mixed 光源** → 只有间接光进入 Lightmap；直接光运行时实时计算并与 Lightmap 的间接光部分叠加 

这样做的代价是需要两张 Lightmap（一张 direct 一张 indirect）或者在 shader 里分开采样，但换来了直接光可以实时变化的能力。

**Shadowmask 方案**：Unity 还提供 Shadowmask 模式，把直接光的阴影信息单独存进一张遮罩图（R32 格式，每通道对应一个光源的可见性），Lightmap 只存间接光。这样动态物体也能通过 Shadowmask 获得正确的直接光阴影 。

### 一张图理清关系

```
                    ┌─ Realtime 光源 ──→ 不进入 Lightmap（运行时实时计算）
                    │
光源 ───────────────┼─ Mixed 光源 ─────→ 间接光烤进 Lightmap
                    │                  直接光运行时实时算
                    │
                    └─ Baked 光源 ────→ 直接光 + 间接光全部烤进 Lightmap
                                        │
                                        ▼
                                    存储内容
                                        │
                                        ├─ 传统：Scalar Irradiance (RGB)
                                        ├─ Directional：Irradiance + 主方向
                                        └─ SH Lightmap：L2 球谐系数 (27 floats)
                                        │
                                        ▼
                                    物体接收
                                        │
                                        ├─ 静态物体 → 采样 Lightmap
                                        └─ 动态物体 → Light Probe 插值
```

### 总结回答你的三个问题

1. **物体必须静态**（Lightmap 绑定 UV，移动就错位）；**光源不一定静态**，但只有 Baked/Mixed 光源才对 Lightmap 有贡献
2. **存的核心是 Irradiance**（辐照度），现代方案扩展为带方向性的辐照度或 SH 系数
3. **Full Bake 下存的是全局光**（直接光 + 间接光的总和）；Mixed 模式下通常只存间接光，直接光留给运行时

> ⚠️ 容易产生误解的一点：很多人以为 Lightmap "只存间接光"，这是不对的。在经典的全烘焙流程中，Lightmap 包含了直接光（带阴影）和间接光两部分——也就是完整的全局光照解。只有在 Mixed/Shadowmask 等高级模式下，才会把直接和间接拆开存储。

## 9. 光栅化 PBRT 软光追 RTX DXR  
先把概念对齐——这几样东西其实**不在同一层**，不能直接"谁比谁好"：

- **"光栅化下的PBRT技术"**：指把 PBRT 这本书里描述的一套物理光照传输算法——路径追踪（Path Tracing）、双向路径追踪（BDPT）、光子映射（Photon Mapping）、MLT 等——的思想**借用光栅化管线的技巧去近似实现**，以便在普通 GPU 上实时跑出全局光照。典型代表是 Square Enix 的"Real-Time Bidirectional Path Tracing via Rasterization"，用 Reflective Shadow Maps + Global Ray Bundles 在 DX11 GPU 上近似 BDPT；PBRT 本身其实是 CPU 离线的物理渲染参考实现，包含上述所有积分器。
- **软光追（Software Ray Tracing）**：直接用通用计算单元（CUDA / Compute / CPU）跑光线与三角形求交，**算法上就是"真"光追**，只是没有专门硬件加速。
- **RTX / DXR / Vulkan 光追**：这三个也不是并列关系。**RTX 是 NVIDIA 的硬件+生态品牌**（RT Core + Tensor Core）；**DXR 是微软在 DirectX 12 里引入的光追 API**；**Vulkan 光追**是通过 `VK_KHR_ray_tracing_pipeline` 等扩展提供的跨平台光追 API。DXR 和 Vulkan RT 都跑在 RT Core 这类专用硬件上——所谓"硬件光追"。

下面按"近似 PBRT 的光栅化技术 vs 软光追 vs 硬件光追（DXR/Vulkan RT）"三层来比。

### 一、光栅化下的"PBRT 类"技术

核心思路：**用光栅化管线的既有硬件（Render-to-Texture、MRT、Compute、硬件裁剪）去近似物理光照方程**，而不是真去追踪每条光线。

常见招式：

- **Reflective Shadow Maps (RSM)**：从光源视角渲一张带法线/位置/通量的 G-Buffer，用来近似"光线从光源发出后的第一次反弹"
- **Light Propagation Volumes (LPV)**：把光照注入 3D 网格体，用传播近似间接光
- **Voxel Cone Tracing**：把场景体素化，用锥形追踪近似漫反射反弹
- **Screen Space GI / SSGI**：屏幕空间内做光线步进近似
- **Square Enix 的 RSM + Global Ray Bundles**：近似完整的 BDPT，在 DX11 GPU 上做到了 1920×1088@动态场景的实时两跳间接光照

> 💡 这类方法的本质是**用"近似算法 + 光栅化硬件"换"物理准确"**。它们能在完全没有 RT Core 的 GPU 上跑，兼容性极好，但都有各自的天花板：RSM 有数值误差和尖刺伪影，LPV 精度有限，SSGI 只能处理屏幕上可见的东西。

### 二、软光追（Software Ray Tracing）

就是**在通用 GPU 核心（CUDA/Compute Shader）甚至 CPU 上跑 BVH 遍历 + 射线-三角形求交**。

- 算法上是"真"光追：每条射线独立求交，物理准确，能做软阴影、多次反射折射、真 GI
- 但**没有 RT Core 这种专用电路**来做 BVH 遍历和射线-三角形测试，所有求交都在通用核心上算，**性能代价巨大**——Pascal 架构跑 Metro Exodus 的光追，同样的工作量 Turing 有 RT Core 后只需 1/5 时间
- 工业界代表：电影工业几十年的离线渲染器（RenderMan、Arnold、Cycles 等）都是软光追；UE 的 Lumen 也提供"SDF 软件光追"模式，对简化版场景求交，能在非 RTX 显卡上跑 GI
- 适合：**离线渲染、对画质极致追求、或者目标硬件没有 RT Core**

### 三、硬件光追：DXR 与 Vulkan RT

两者**设计理念高度相似**——都引入加速结构（BVH）、光线生成着色器、命中着色器、Shader Binding Table 这套模型，差别主要在生态和显式程度：

| 维度 | DXR (DirectX 12) | Vulkan Ray Tracing |
|---|---|---|
| **平台** | Windows / Xbox 原生 | 跨平台：Win / Linux / Android / 部分主机 |
| **硬件抽象** | 加速结构 + 状态对象 + 着色器表（Shader Table） | BLAS/TLAS 显式创建，管线/着色器组手动拼装 |
| **控制粒度** | 相对高层，根签名体系管理资源 | 极显式，几乎所有东西手动管理，学习曲线陡 |
| **着色器** | HLSL → DXIL | HLSL→SPIR-V 或 GLSL→SPIR-V |
| **工具链** | Visual Studio + PIX，调试体验极佳 | RenderDoc / Nsight，光追调试有 caveats |
| **硬件加速** | 调用 NV/AMD/Intel 的 RT Core / Ray Accelerator | 同样调用各家 RT 硬件 |

> 📌 **RTX 不是独立于 DXR/Vulkan 的第三种选择**——RTX 是 NVIDIA 的硬件（RT Core + Tensor Core）+ 驱动 + 工具链品牌，**上层 API 在 Windows 上就是 DXR，跨平台就是 Vulkan RT**。AMD 的 Ray Accelerator、Intel 的 RT Unit 同理。

DXR 还有个独门特性叫 **Inline Raytracing**（Tier 1.1+）：不需要独立的 Shader Table 和动态着色器，直接在 Compute/Pixel Shader 里用 `RayQuery` 对象做求交——这其实就是 Vulkan 里 `rayQuery` 的对应物，移动端轻量级光追常用。

### 四、横向量化对比

| 维度 | 光栅化 PBRT 近似 | 软光追 | 硬件光追（DXR / Vulkan RT） |
|---|---|---|---|
| **物理准确性** | 近似，各有伪影 | 精确 | 精确 |
| **实时性** | ✅ 轻松 60+ FPS | ❌ 通常个位数 FPS | ✅ 可控 30-120 FPS（取决于弹射次数） |
| **硬件依赖** | 任意 GPU | 任意 GPU（通用计算） | 需要 RT Core / Ray Accelerator |
| **实现复杂度** | 中（要懂各种近似算法的坑） | 高（BVH 构建、遍历调度全自己写） | 中（API 复杂但有硬件兜底） |
| **典型场景** | 手游、WebGL、老硬件、全平台兜底 | 影视离线、烘焙、Lumen SDF 模式 | 3A 游戏的实时反射/阴影/GI |
| **代表** | RSM / LPV / VXGI / Lumen 光栅版 | RenderMan / Arnold / Cycles | UE5 Lumen HW RT、Cyberpunk RTX |

### 五、工业界真实做法：混合管线

现代 3A 引擎**不会纯用某一种**，而是**光栅打底 + 光追补光照**：

1. **光栅阶段**：Mesh Shader 渲 GBuffer、深度缓冲、硬件剔除——这一步光栅比光追高效得多，因为光栅天生按屏幕像素遍历，有 Early-Z、Hi-Z 等成熟硬件
2. **硬件光追阶段**：用 RT Core 发阴影光线、反射光线、漫反射 GI 反弹光线、AO 光线
3. **Compute 阶段**：ReSTIR 样本复用、降噪、AI 超分（DLSS/FSR）
4. **光栅后处理**：Bloom、Tone Mapping、TAA 等纯 2D 操作

> ⚠️ 关键点：**光栅化和光追不是替代关系，而是分工**。光栅化负责"把三角形变成屏幕像素"这件它极擅长的事；光追负责"算物理光照传输"这件光栅化很难低成本做对的事（软阴影、多次反射、真 GI）。

### 六、怎么选

- **目标硬件没有 RT Core**（手游、WebGL、老 PC）：只能用**光栅化 PBRT 近似**那一套——RSM/LPV/SSGI/Lumen 光栅版。质量上限受限于近似算法的固有缺陷。
- **需要离线影视级画质**：**软光追**路径追踪，慢慢算，PBRT 本身就是这么用的。
- **Windows / Xbox 平台的实时 3A**：DXR + RTX，工具链最成熟，PIX 调试体验最好。
- **跨平台（Linux/Android/多 GPU）**：Vulkan RT，代价是学习曲线陡、要手动管理大量细节。
- **追求电影级实时**：混合管线——光栅 GBuffer 打底 + RTX 硬件光追补光照 + Compute 降噪，这是 2026 年 3A 和数字孪生的主流方案。

> 💡 一个常被忽略的点：即便你有 RT Core，**主光线（Primary Ray）仍然是用光栅化画的**，而不是真的从相机发射光线去做最近命中测试——后者每个像素都要遍历 BVH，纯属浪费。光追只接管"次级光线"（阴影、反射、GI 弹跳）。所以"光栅化 PBRT 技术"和"硬件光追"在现代引擎里**是合作关系，不是选择题**。


## 10. 光线追踪 路径追踪 光子映射  比较
这三个词经常被混着用，但它们**不在同一个抽象层级**。先理清概念边界，再比较算法特性。

### 一、概念层级：谁是父类，谁是子类

```
光线追踪 (Ray Tracing) ── 广义：一切"沿光线传播求交"的渲染方法总称
       │
       ├── 光线追踪 (Ray Tracing) ── 狭义：Whitted 1980 年提出的经典算法
       │      特点：从相机发射光线，碰到镜面/折射继续反射/折射，
       │            碰到漫反射表面则向光源发"阴影光线"判可见性
       │
       ├── 路径追踪 (Path Tracing) ── Kajiya 1986，基于渲染方程的 MC 求解
       │      特点：从相机发射光线，在每个交点随机选一个方向继续走，
       │            形成一条完整路径，直到逃逸或达到最大深度
       │
       └── 光子映射 (Photon Mapping) ── Jensen 1996，粒子追踪 + 密度估计
              特点：从光源发射光子，在场景中弹射并记录光子贴图，
                    最后通过局部密度估计求 irradiance
```

> 📌 **关键澄清**：日常语境里"光线追踪"常作为**总称**——此时路径追踪、光子映射都是它的子类；但在学术论文里"Ray Tracing"特指 Whitted 式算法，与 Path Tracing 并列。下文按**并列的具体算法**来比较。

### 二、三种算法的核心机制

#### 1. 光线追踪（Whitted 式）

**思路**：光线只从相机发出，递归地：

- 命中**理想镜面/折射面** → 按反射/折射定律继续追踪
- 命中**漫反射面** → 停止递归，向每个光源发一条"阴影光线"判断可见性，做直接光照

**本质**：只处理**直接光照 + 镜面/折射的间接光照**，**漫反射表面的间接光照（color bleeding、柔和阴影）算不出来**。

#### 2. 路径追踪（Path Tracing）

**思路**：从相机发射光线，在每个交点：

- 按 BSDF 的重要性采样随机选一个新方向
- 递归追踪，直到击中光源或达到最大深度或俄罗斯轮盘赌终止

一条路径是一个蒙特卡洛样本，**对所有可能的光路求期望**。

**本质**：**无偏估计**，理论上能收敛到渲染方程的精确解，包括所有次数的漫反射间接光。

#### 3. 光子映射（Photon Mapping）

**两趟（two-pass）算法**：

- **Pass 1（光子发射）**：从光源发射 N 个光子，按 BSDF 随机弹射，记录在场景中的分布 → 形成光子贴图
- **Pass 2（渲染）**：从相机发射光线，在漫反射表面交点处，取周围 k 个最近光子做**密度估计**求得 irradiance

**本质**：**有偏但一致（biased but consistent）**——偏差来自密度估计的核带宽，随着光子数增加、带宽缩小，偏差趋于 0。

### 三、量化对比

| 维度 | 光线追踪 (Whitted) | 路径追踪 | 光子映射 |
|---|---|---|---|
| **理论依据** | 递归光线 + 阴影线 | 渲染方程的 MC 估计 | 粒子追踪 + 密度估计 |
| **漫反射间接光** | ❌ 不支持 | ✅ 完整支持 | ✅ 完整支持 |
| **焦散 (Caustics)** | ❌ 不支持 | ⚠️ 极难收敛（需要光子碰巧打到焦散接收面） | ✅ 天然擅长 |
| **镜面/光泽反射** | ✅ 完美 | ✅ 完美 | ⚠️ 需要特殊 BSDF 处理 |
| **估计性质** | 确定性算法 | 无偏（unbiased） | 有偏但一致（biased but consistent） |
| **收敛速度** | 一步到位无噪声 | 慢，需要大量 SPP + 降噪 | 较快，但有参数敏感问题 |
| **实现复杂度** | 低 | 中 | 高（需要 KD-Tree / 光子贴图管理） |
| **典型用途** | 早期 CGI、CAD 预览 | 离线影视渲染主流（Disney、Pixar） | 焦散场景、参与介质、烟雾渲染 |

### 四、各自的"死穴"

#### 光线追踪的死穴
**不能处理漫反射间接光照**。一个红墙旁边的白墙，Whitted 光线追踪渲出来还是白的——没有 color bleeding。这是因为它在漫反射表面就停了，没有继续弹射。

#### 路径追踪的死穴
**漫反射→镜面→光源**这类光路极难采样到。比如：

```
相机 → 漫反射地面 → 镜面金属球 → 光源
```

这条路径的概率极低，导致焦散、镜面反射里的光源高光等效果**收敛极慢，噪声巨大**。这也是为什么现代路径追踪要引入**下一代技术**：

- **Bidirectional Path Tracing (BDPT)**：从相机和光源两边发路径，连接成完整光路
- **Metropolis Light Transport (MLT)**：基于马尔可夫链的重要度采样，专门攻克困难光路
- **Vertex Connection Merging (VCM)**：BDPT + 光子映射的混合
- **ReSTIR**：实时化的样本复用技术

#### 光子映射的死穴
**密度估计的偏差问题**。光子数少了 → 噪声大；光子数多了 → 内存爆炸。而且在漫反射表面做 k-NN 密度估计时，**核带宽的选择**直接影响质量——带宽太大糊一片，太小全是噪点。这就是为什么 Jensen 后来提出了 **Progressive Photon Mapping (PPM)** 和 **Stochastic Progressive Photon Mapping (SPPM)**，用渐进式迭代让偏差逐渐归零。

### 五、现代工业界的实际选择

- **离线影视渲染**：**路径追踪为主流**。Pixar RenderMan 的 RIS、Disney Hyperion、Blender Cycles、Arnold 全都基于路径追踪及其变种（BDPT/MLT/VCM）。原因：无偏、物理准确、易于实现复杂的 BSDF。
- **焦散/参与介质场景**：**光子映射或其变种仍有一席之地**。特别是在水底焦散、烟雾、云这类场景中，光子映射的"从光源发射"特性比路径追踪的"从相机发射"更有优势。
- **实时渲染（游戏）**：**路径追踪 + 降噪**是方向。NVIDIA RTX 的 RT Core 就是为加速路径追踪的 BVH 遍历而生；UE5 Lumen、Cyberpunk 2077 的 RT 模式本质上都是在做实时路径追踪，然后用 AI 降噪（DLSS/NN denoiser）把噪声压下去。
- **Whitted 光线追踪**：现代基本不用作独立算法，但它的**思想**（递归光线 + 阴影线）被路径追踪继承。

### 六、一句话总结它们的差异

- **光线追踪**："我从相机看过去，看到什么就是什么，漫反射表面只看光源"——**只能处理直接光 + 镜面间接光**
- **路径追踪**："我从相机出发，随机游走，对所有可能的光路求平均"——**无偏，能算所有间接光，但某些光路收敛慢**
- **光子映射**："我从光源出发，把光子撒进场景，最后数一数每个点周围有多少光子"——**有偏但一致，天然擅长焦散和参与介质**

> 💡 现代高端渲染器（如 RenderMan、Hyperion）的做法是**混合**：以路径追踪为主框架，针对焦散/参与介质等特殊效果引入光子映射的思路，再用降噪和样本复用技术加速收敛。没有一种银弹，都是组合拳。

## 11. Cook-Torrance 各项取值范围

### 结论速查

| 项 | 单位 | 取值范围 | 能否 >1？ | 原因 |
|---|---|---|---|---|
| $F$（Fresnel） | 无量纲 | $[0, 1]$ | ❌ 不能 | 能量反射比例 |
| $G$（Masking-Shadowing） | 无量纲 | $[0, 1]$ | ❌ 不能 | 可见微表面概率 |
| $D$（NDF） | $\text{sr}^{-1}$ | $[0, +\infty)$ | ✅ 可以 | 法线方向密度 |
| $f_r$（BRDF） | $\text{sr}^{-1}$ | $[0, +\infty)$ | ✅ 可以 | 方向反射率密度 |

---

### 1. $F$ — Fresnel 项：$[0, 1]$

**物理意义**：单个微表面镜面反射的能量占入射能量的比例。

$$
F(\omega_o, \omega_h) = \frac{\text{反射通量}}{\text{入射通量}} \in [0, 1]
$$

- Schlick 近似：$F = F_0 + (1-F_0)(1-\cos\theta)^5$，当 $F_0 \in [0,1]$ 时 $F \in [F_0, 1]$
- 正入射：$F = F_0$（最小）
- 掠射角：$F \to 1$（最大，全反射）
- **永远不可能大于 1**，因为能量不能凭空产生

---

### 2. $G$ — Masking-Shadowing 项：$[0, 1]$

**物理意义**：法线为 $\omega_h$ 的微表面中，**既被光源看到、又被观察者看到**的比例。

$$
G(\omega_i, \omega_o, \omega_h) = \frac{\text{可见微表面面积}}{\text{总微表面面积}} \in [0, 1]
$$

- Smith $G_1$ 单方向可见概率 $\in [0, 1]$
- 联合 $G = G_1(\omega_i) \cdot G_1(\omega_o)$（独立假设）或更精确的联合形式，仍 $\in [0, 1]$
- **永远不可能大于 1**，因为是子集比例

---

### 3. $D$ — NDF 法线分布函数：可以远大于 1 ⚠️

**物理意义**：单位立体角内、单位宏观面积上，法线为 $\omega_h$ 方向的微表面**面积密度**。

$$
dA_h = D(\omega_h)\,d\omega_h\,dA
$$

**关键**：$D$ 是密度（单位 $\text{sr}^{-1}$），不是概率。归一化条件是带 $\cos\theta_h$ 加权的积分：

$$
\int_{\Omega} D(\omega_h)\,\cos\theta_h\,d\omega_h = 1
$$

**不是** $\int D\,d\omega = 1$，所以 $D$ 本身**没有上界 1**。

**GGX 示例**：

$$
D(\omega_h) = \frac{\alpha^2}{\pi\left((\mathbf{n}\cdot\omega_h)^2(\alpha^2-1)+1\right)^2}
$$

正入射方向（$\mathbf{n}\cdot\omega_h = 1$）：

$$
D_{\max} = \frac{1}{\pi\,\alpha^2}
$$

| 粗糙度 $\alpha$ | $D_{\max} = 1/(\pi\alpha^2)$ | 是否 >1 |
|---|---|---|
| 1.0（完全粗糙） | $\approx 0.318$ | ❌ |
| 0.5 | $\approx 1.27$ | ✅ |
| 0.1（较光滑） | $\approx 31.8$ | ✅ 远大于 |
| 0.01（近镜面） | $\approx 3183$ | ✅ 极大 |
| $\to 0$（完美镜面） | $\to +\infty$ | ✅ 趋向 δ 函数 |

**物理直觉**：表面越光滑，所有微表面法线越集中在 $\mathbf{n}$ 附近，密度峰值越高。极限情况退化为 Dirac δ 函数，$D \to \infty$。

---

### 4. $f_r$ — BRDF：可以大于 1 ⚠️

**单位**：$\text{sr}^{-1}$（每球面度），不是无量纲。

**能量守恒约束**是**积分形式**，不是逐点约束：

$$
\int_{\Omega} f_r(\omega_i, \omega_o)\,\cos\theta_o\,d\omega_o \leq 1
$$

这意味着：**单个方向上 $f_r$ 完全可以大于 1**，只要积分总能量不超过入射能量。

**典型例子**：
- **完美镜面**：$f_r = \delta(\omega_o - R(\omega_i))$，在镜面方向为无穷大
- **高光泽金属**（$\alpha=0.05$）：镜面方向 $f_r$ 可达数百甚至上千
- **Lambert 漫反射**：$f_r = \rho/\pi \leq 1/\pi \approx 0.318$（这里刚好 <1，但只是巧合）

**反例直觉**：一束光打在镜子上，几乎所有能量都反射到**一个方向**。那个方向的 radiance 远超入射 radiance（浓缩了整个半球的能量），$f_r$ 自然很大。

---

### 数值验证：高光泽金属

取 $\alpha = 0.1$，$\omega_i = \omega_o = \mathbf{n}$（正入射）：

| 项 | 数值 |
|---|---|
| $F$ | $\approx 0.9$（金属 $F_0$） |
| $G$ | $\approx 1.0$（正入射无遮挡） |
| $D$ | $\approx 31.8$ |
| 分母 $4\cos\theta_i\cos\theta_o$ | $4$ |
| **$f_r$** | $\approx 0.9 \cdot 1.0 \cdot 31.8 / 4 \approx 7.16$ |

$f_r \approx 7.16\;\text{sr}^{-1}$，**远大于 1**，完全合法。

---

### 常见误区

| 误区 | 正确理解 |
|---|---|
| "BRDF 必须 ≤ 1" | ❌ BRDF 单位是 $\text{sr}^{-1}$，可远大于 1；约束是**积分能量守恒** |
| "D 必须 ≤ 1" | ❌ D 是密度，归一化带 $\cos\theta_h$ 权重，峰值无上界 |
| "F 和 G 可以 >1" | ❌ 这两个是真正的比例/概率，严格 $\in [0,1]$ |
| "光滑表面 D 小" | ❌ 反过来：越光滑 D 峰值越大（能量越集中） |

---

### 一句话总结

> **$F, G \in [0,1]$** 是物理比例；**$D, f_r$ 可以大于 1** 是方向密度（单位 $\text{sr}^{-1}$），受积分能量守恒约束而非逐点上界。光滑金属在镜面方向 $f_r$ 可达数十甚至上千，完全正常。

## 12. $D$ 与概率密度的关系

### 结论

**$D(\omega_h)$ 不是严格意义上的概率密度**，但**与一个相关概率密度 $p(\omega_h)$ 仅差一个 $\cos\theta_h$ 因子**。二者通过归一化条件区分。

---

### 1. 数学定义对比

| 量 | 归一化条件 | 单位 | 性质 |
|---|---|---|---|
| **概率密度** $p(\omega_h)$ | $\displaystyle\int_\Omega p(\omega_h)\,d\omega_h = 1$ | $\text{sr}^{-1}$ | 严格 PDF |
| **NDF** $D(\omega_h)$ | $\displaystyle\int_\Omega D(\omega_h)\cos\theta_h\,d\omega_h = 1$ | $\text{sr}^{-1}$ | **投影加权**密度 |

**关键区别**：$D$ 的归一化带 $\cos\theta_h$ 权重，$p$ 不带。所以 $D \neq p$。

---

### 2. 二者的精确换算关系

由 NDF 的物理定义（pbrt eq 8.15）：

$$
dA_h = D(\omega_h)\,d\omega_h\,dA
$$

其中 $dA_h$ 是法线落在 $\omega_h$ 附近 $d\omega_h$ 内的**微表面总表面积**，$dA$ 是宏观面积。

把 $dA_h$ 投影到宏观法线 $\mathbf{n}$ 方向（投影面积 = $\cos\theta_h \cdot dA_h$），归一化条件要求"所有微表面投影面积之和 = 宏观面积"：

$$
\int_\Omega \underbrace{D(\omega_h)\cos\theta_h\,d\omega_h}_{=:\,p(\omega_h)} = 1
$$

因此：

$$
\boxed{\;p(\omega_h) = D(\omega_h)\,\cos\theta_h\;}
$$

**这才是真正的概率密度**——"在宏观面积上随机取一点，其微表面法线落在 $\omega_h$ 附近的概率密度"。

---

### 3. 为什么 $D$ 要带 $\cos\theta_h$ 权重？

**几何原因**：投影面积守恒。

| 量 | 几何意义 |
|---|---|
| $D\,d\omega_h\,dA$ | 法线在 $\omega_h$ 附近的微表面**真实面积** |
| $D\cos\theta_h\,d\omega_h\,dA$ | 这些微表面**投影到宏观表面**的面积 |

**归一化对象是投影面积，不是真实面积**：

- 宏观表面 $dA$ 看到的"覆盖"是微表面投影后的总和
- 倾斜的微表面（$\theta_h$ 大）真实面积大，但投影到宏观表面只占很小一块
- 所以 $D$ 必须乘 $\cos\theta_h$ 才是"占宏观面积的比例"

如果强行用 $\int D\,d\omega = 1$ 归一化，倾斜微表面会被**过度计数**——这是初学者常见错误。

---

### 4. 数值对比：GGX 在 $\alpha = 0.3$ 时

正入射方向 $\omega_h = \mathbf{n}$（$\cos\theta_h = 1$）：

$$
D(\mathbf{n}) = \frac{1}{\pi\alpha^2} = \frac{1}{\pi \cdot 0.09} \approx 3.54
$$

$$
p(\mathbf{n}) = D(\mathbf{n})\cos\theta_h = 3.54 \times 1 = 3.54
$$

掠射方向 $\theta_h = 80°$（$\cos\theta_h \approx 0.174$）：

$$
D(\omega_h) \approx 0.05 \quad\text{(GGX 尾部)}
$$

$$
p(\omega_h) = 0.05 \times 0.174 \approx 0.0087
$$

**对比**：

| 方向 | $D(\omega_h)$ | $p(\omega_h) = D\cos\theta_h$ | 比值 $D/p$ |
|---|---|---|---|
| 正入射 ($\cos=1$) | 3.54 | 3.54 | 1.0 |
| 掠射 ($\cos=0.174$) | 0.05 | 0.0087 | 5.75 |

掠射方向 $D$ 比 $p$ 大 5.75 倍——这就是 $\cos\theta_h$ 权重的体现。

---

### 5. 蒙特卡洛采样中的用法

**重要性采样**时，采样的必须是**概率密度 $p$**，不是 $D$：

$$
\omega_h \sim p(\omega_h) = D(\omega_h)\cos\theta_h
$$

估计量：

$$
f_r \approx \frac{1}{N}\sum_{j=1}^N \frac{g(\omega_h^{(j)})}{p(\omega_h^{(j)})}
$$

**常见错误**：直接用 $D$ 当 PDF 采样，会导致掠射方向**过采样**（因为 $D$ 在掠射处相对 $p$ 偏大），方差爆炸。

pbrt / Mitsuba / GLSL 实现：GGX 采样公式

$$
\cos\theta_h = \sqrt{\frac{1-\xi_1}{\alpha^2\xi_1 + 1 - \xi_1}},\quad \phi_h = 2\pi\xi_2
$$

这个公式对应的 PDF 正是 $D(\omega_h)\cos\theta_h$，而不是 $D$ 本身。

---

### 6. 为什么大家都把 $D$ 叫"分布"而不是"密度"

**术语习惯**：
- **Normal Distribution Function** 字面是"法线分布函数"，强调"分布形状"
- 物理意义上 $D$ 描述"微表面法线的浓度分布"
- 但严格数学上它是"投影加权密度"，不是纯概率密度

**类比**：
- 辐射亮度 $L$（radiance）单位 $\text{W}\cdot\text{sr}^{-1}\cdot\text{m}^{-2}$ 也是"密度"，但不是概率密度
- $D$ 类似——是**物理量的密度**，需要适当加权才能转化为概率密度

---

### 一句话总结

| 提法 | 是否准确 |
|---|---|
| "$D$ 是概率密度" | ❌ 不严谨，缺 $\cos\theta_h$ 权重 |
| "$D$ 是微表面法线的方向密度" | ✅ 物理意义正确 |
| "$D\cos\theta_h$ 才是概率密度 $p$" | ✅ 严格数学定义 |
| "采样时用 $D$ 当 PDF" | ❌ 错误，应该用 $p = D\cos\theta_h$ |

> **$D$ 是"几何浓度密度"（带面积量纲的物理密度），$p = D\cos\theta_h$ 才是归一化后的"概率密度"。两者差一个投影因子 $\cos\theta_h$，这正是微表面投影几何的体现。**

## 13. 你的疑问都切中要害——图形学符号确实经常"一符多义"

### 0. 三个核心问题的速答

| 问题 | 速答 |
|---|---|
| $\theta_h$ 是和 $\mathbf{n}$ 还是 $\omega_i$ 的夹角？ | **pbrt 中是和 $\mathbf{n}$ 的夹角**，但 $\cos\theta_h = \omega_i \cdot \omega_h$ 同时成立（巧合，因 $\omega_h$ 平分 $\omega_i, \omega_o$） |
| $\omega_i, \omega_h$ 是立体角还是方向？ | **同一符号双重含义**：既表示"方向向量"，也表示"该方向对应的立体角微元/区域" |
| 立体角不是"面积/半径²"吗？怎么成了方向？ | **立体角是"方向的范围"**，单点方向是它的退化情形；图形学习惯把"方向"和"该方向的立体角"混用 |

---

### 1. $\theta_h$ 的定义（pbrt 原文）

**pbrt 3ed §8.4.2**：

> $\theta_h$ is the angle between $\omega_h$ and the surface normal $\mathbf{n}$.

明确是 **$\omega_h$ 与宏观法线 $\mathbf{n}$ 的夹角**，不是与 $\omega_i$ 的夹角。

**但同时 pbrt 又写** $\cos\theta_h = \omega_i \cdot \omega_h$ —— 这看似矛盾，其实不矛盾，原因是下面的"等角性"。

---

### 2. 为什么 $\cos\theta_h = \omega_i \cdot \omega_h$ 同时成立？

**关键事实**：$\omega_h$ 是 $\omega_i$ 和 $\omega_o$ 的**半角向量**，它**平分** $\omega_i$ 与 $\omega_o$ 的夹角。

**几何推导**：

设 $\alpha = \angle(\omega_i, \mathbf{n})$，$\beta = \angle(\omega_o, \mathbf{n})$，则：

$$
\angle(\omega_i, \omega_h) = \frac{\alpha + \beta}{2}, \qquad \angle(\omega_h, \mathbf{n}) = \frac{|\alpha - \beta|}{2}
$$

**这两种情形**：

#### 情形 A：一般入射（$\alpha \neq \beta$）

$\theta_h$（与 $\mathbf{n}$ 夹角）**不等于** $\angle(\omega_i, \omega_h)$。此时 pbrt 的 $\cos\theta_h = \omega_i \cdot \omega_h$ **看起来是错的**——但其实 pbrt 在那里用的符号 $\theta_h$ 是**另一定义**！

#### 情形 B：pbrt 推导 Torrance-Sparrow 时的特殊符号

pbrt 在 §8.4.4 推导立体角变换时，**临时把 $\theta_h$ 重新定义为 $\angle(\omega_i, \omega_h)$**（即半角与入射的夹角），而非与 $\mathbf{n}$ 的夹角。这是 **pbrt 的符号重载**（symbol overload），容易让读者困惑。

**两种 $\theta_h$ 定义并存**：

| 出处 | $\theta_h$ 定义 | $\cos\theta_h$ 等于 |
|---|---|---|
| pbrt §8.4.2（NDF 定义 GGX/Beckmann） | $\angle(\omega_h, \mathbf{n})$ | $\omega_h \cdot \mathbf{n}$ |
| pbrt §8.4.4（Torrance-Sparrow 推导） | $\angle(\omega_i, \omega_h)$ | $\omega_i \cdot \omega_h$ |

**巧合统一**：当 $\omega_o = \omega_i$（正入射，$\omega_h = \mathbf{n}$）时，两种定义数值相同。一般情形下不同。

我在前一条回答里**混用了这两种定义**——这是我的疏忽。应明确：**Torrance-Sparrow 分母 4 的推导用的是 $\theta_h = \angle(\omega_i, \omega_h)$**，而 **GGX/Beckmann 公式 $D(\theta_h)$ 里的 $\theta_h = \angle(\omega_h, \mathbf{n})$**。

---

### 3. $\omega_i, \omega_h$ 到底是方向还是立体角？

**答：同一符号，根据上下文两种含义**。这是图形学的"约定俗成"，但确实容易混淆。

#### 含义 1：单位方向向量

$$
\omega_i \in \mathbb{S}^2, \quad \|\omega_i\| = 1
$$

表示"光线传播方向"，可以做点积 $\omega_i \cdot \omega_h$。

#### 含义 2：该方向对应的立体角微元

$$
d\omega_i = \text{以方向 }\omega_i\text{ 为中心的微小立体角}
$$

单位是球面度 $\text{sr}$。

**pbrt 原文（§5.4）**：

> "Directions are denoted by $\omega$, and we will use the convention that $\omega$ is a normalized vector. ... A differential solid angle $d\omega$ is associated with a direction $\omega$."

**翻译**：$\omega$ 是单位向量表示方向；$d\omega$ 是该方向附近的微分立体角。所以同一个 $\omega$ 既是"方向"又是"该方向的立体角"，看上下文。

#### 为什么图形学要这么混用？

因为渲染方程里"方向"和"立体角"几乎总是成对出现：

$$
L_o(\omega_o) = \int_\Omega f_r(\omega_i, \omega_o)\,L_i(\omega_i)\,\cos\theta_i\,\underbrace{d\omega_i}_{\text{立体角}}
$$

积分变量是 $d\omega_i$（立体角），但被积函数里的 $\omega_i$ 是方向。**为了简化，把"$\omega_i$ 方向 + 它的 $d\omega_i$"统一记作 $\omega_i$**，这是数学物理的常见做法（如统计力学里的"相空间坐标"）。

---

### 4. "立体角 = 面积/半径²"——这跟"方向"矛盾吗？

**不矛盾**。立体角本质是**"方向的范围"**，"面积/半径²"只是它的**度量方式**。

#### 类比：平面角 vs 方向（2D）

| 2D | 3D |
|---|---|
| 平面角 $\theta \in [0, 2\pi)$ | 立体角 $\omega \in [0, 4\pi)$ |
| "弧长/半径" | "面积/半径²" |
| 表示一个**方向**（如"东偏北 30°"） | 表示一个**方向**（如"球面上的某点"） |
| 角度区间 $d\theta$ 表示"方向的小范围" | 立体角 $d\omega$ 表示"方向的小锥形范围" |

**关键洞察**：
- 单位球面上的一点 ↔ 一个方向 ↔ 一个"无穷小立体角"
- 球面上一块区域 ↔ 一组方向 ↔ 一个有限立体角
- **方向是立体角的退化情形**（点 = 极小区域）

所以"$\omega_i$ 是方向"和"$\omega_i$ 是立体角"本质是同一件事的两种说法——前者强调"指向哪"，后者强调"占多大范围"。

---

### 5. 为什么 $d\omega_i = 4\cos\theta_h\,d\omega_h$（用统一的 $\theta_h$ 定义）

**正确推导（采用 pbrt §8.4.4 的定义 $\theta_h = \angle(\omega_i, \omega_h)$）**：

固定 $\omega_o$，$\omega_h$ 决定 $\omega_i$（反射定律：$\omega_i = 2(\omega_o \cdot \omega_h)\omega_h - \omega_o$）。

取 $\omega_o$ 为极轴建立球面坐标。设 $\omega_h$ 相对 $\omega_o$ 的极角为 $\theta_h$（这里 $\theta_h = \angle(\omega_i, \omega_h) = \angle(\omega_o, \omega_h)$，因为 $\omega_h$ 平分二者），方位角 $\phi$：

$$
d\omega_h = \sin\theta_h\,d\theta_h\,d\phi
$$

$\omega_i$ 相对 $\omega_o$ 的极角是 $2\theta_h$（二倍角关系），方位角 $\phi + \pi$（反射后方位反向，但 $d\phi$ 大小相同）：

$$
d\omega_i = \sin(2\theta_h)\,d(2\theta_h)\,d\phi = 2\sin\theta_h\cos\theta_h \cdot 2\,d\theta_h\,d\phi = 4\cos\theta_h\,\underbrace{\sin\theta_h\,d\theta_h\,d\phi}_{=d\omega_h}
$$

$$
\boxed{\;d\omega_i = 4\cos\theta_h\,d\omega_h\;}\quad\text{其中 }\theta_h = \angle(\omega_i, \omega_h)
$$

**这里的 $\theta_h$ 是 $\omega_i$ 与 $\omega_h$ 的夹角**，所以 $\cos\theta_h = \omega_i \cdot \omega_h$ **是定义，不是巧合**。

### 6. 符号澄清表（最终版）

| 符号 | 严格定义 | 备注 |
|---|---|---|
| $\mathbf{n}$ | 宏观表面法线（单位向量） | 不变 |
| $\omega_i$ | 入射方向（单位向量） | 同时表示该方向立体角 |
| $\omega_o$ | 出射方向（单位向量） | 同时表示该方向立体角 |
| $\omega_h$ | 半角向量 $= \text{normalize}(\omega_i + \omega_o)$ | = 微表面法线 |
| $\theta_h$（NDF 公式里） | $\angle(\omega_h, \mathbf{n})$ | GGX/Beckmann 的自变量 |
| $\theta_h$（Torrance-Sparrow 推导里） | $\angle(\omega_i, \omega_h) = \angle(\omega_o, \omega_h)$ | 用于立体角变换 |
| $d\omega_i$ | $\omega_i$ 方向的微分立体角 | 单位 sr |
| $D(\omega_h)$ | NDF，描述 $\omega_h$ 方向的法线浓度 | 单位 sr⁻¹ |

**关键关系**：

- 反射定律：$\omega_h$ 平分 $\omega_i, \omega_o$，所以 $\angle(\omega_i, \omega_h) = \angle(\omega_o, \omega_h)$
- 当 $\omega_o = \mathbf{n}$（视角沿法线）时，两种 $\theta_h$ 定义重合
- 一般情形下，Torrance-Sparrow 推导里的 $\cos\theta_h = \omega_i \cdot \omega_h$ **用的是 $\angle(\omega_i, \omega_h)$ 这一定义**

---

### 一句话总结

> **$\omega$ 在图形学里既是"单位方向向量"又是"该方向的立体角"，看上下文**。$\theta_h$ 在 NDF 公式里是与 $\mathbf{n}$ 的夹角，在 Torrance-Sparrow 立体角变换推导里是与 $\omega_i$ 的夹角——pbrt 用同一符号 $\theta_h$ 表达两个不同量，这是**符号重载**导致的混淆，但两种定义下 $\omega_h$ 都是同一个半角向量。
